## Accepted decisions and adopted design

The operator approved implementation in the same session after the native plan. Approved choices include SQLite plus pinned-artifact bundles, fresh-directory restore, raw-export compatibility and public recovery first. Release installation, service activation, pushing, merging and deployment are outside this delivery. Native self-build state is preserved without claiming its complete session/publication recovery path.

The [normative specification](../41-backup-and-upgrade.md) defines exclusive bundle completion, exact artifact retention, the maintenance marker, transactional migration/fencing and independent recovery checks. Frozen operation/configuration identities are retained. Credentials and external resource/provider stores remain independently managed.

## Implementation evidence

- `backup --bundle` uses SQLite's online backup API, then inventories the completed snapshot. Tests restore committed WAL-backed records and load an original session provider after the original artifact paths disappear and the current lock selects a different version. A throwing artifact module is copied without evaluation. Raw `backup FILE` remains covered.
- `restore` validates bundle checksums, identity, known migration history, SQLite integrity/foreign keys and artifact inventory before publishing to a fresh protected state directory. A durable marker and service lock prevent partial state from activating. Existing files and incomplete bundles remain preserved.
- `upgrade --backup` completes a pre-upgrade bundle and retains artifacts before applying migrations and the recovery fence atomically. A failing DDL migration rolls back version/schema records with active handles intact. A v19 backup restores through migration 20 with the original profile/handle retained.
- Recovery checks include fresh operation observations, sessions and pending projections. Tests preserve pending hook deduplication, session identity, uncertain write tokens and human-edited values. Stale epochs, delayed receipts and unknown observations cannot satisfy fresh checks. Closed/detached sessions are distinguished from delayed closes needing independent confirmation.
- Actual SIGKILL boundaries cover upgrade before migration commit and after commit, plus restore after marker creation, before publication and after publication. Retained directories remain blocked by `maintenance_incomplete`; their complete bundles restore to a different fresh directory.
