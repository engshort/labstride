# W02.3 — Isolate blocked item history

Scope: LS-GH-003 and the LS-OPS-001 recovery surface. Requirement and acceptance statuses remain unchanged.

A native single-select field can expose its current selected option while its actor-bearing Added event has neither a value nor options. Reconciliation correctly refuses that item's ambiguous transition. The previous worker then promoted the item diagnostic into a stream error before processing later items or admitting their independently valid candidates. A local two-item reproduction confirmed zero admissions for a valid second item.

The corrected worker keeps item diagnostics local. A failed classification retains its previous snapshot, unconsumed events and error, and retries at the next enumeration instead of every worker tick. Other items continue. An earlier pending candidate for a blocked item cannot bypass the new diagnostic. Transport/credential/budget/cursor failures retain their existing stream backoff. Inspection adds a blocked-item count and Doctor exposes a separate warning.

The explicit `provider rebaseline ITEM_ID` CLI takes the existing kernel service lock and requires local operator authority. It only accepts an item in the active installation/provider configuration with no earlier request. It supersedes pending candidates without deleting identities, preserves original history, records an operator audit entry and schedules an inert observation. A fresh later authorized transition remains necessary. No database migration, automatic reset, financial action or effect replay is introduced.

Regression cases exercise two independent items, retry cadence, preservation of the blocked item's diagnostics, an older pending candidate with an unchanged current snapshot, denied recovery without authority, inert recovery, fresh subsequent admission and refusal after an earlier request. Existing history ordering, delayed events, cursor recovery, projection, native-field and service-lock tests cover the surrounding behavior.

Type checking of 116 generated contracts passed. The locked Python documentation validator passed 719 local file links, 83 schema/example pairs and rejection cases, and the canonical backlog/checklist checks. These are scoped checks, not a full-suite or installed-service acceptance claim.
