# Named issue-to-review installations

Before the correction, a rejected observation for a second valid workspace could replace the bridge's in-memory report binding. The next valid native report was acknowledged and stored against the second workspace. The regression creates two actual local Git checkouts with protected receipts, rejects the observation for the mismatched working directory, and checks the journal. The corrected bridge keeps the original binding and recovers the journaled report when it is reopened. An installation-scoped bridge also rejects a valid receipt from a different installation.

The bootstrap regression applies the default and named layouts to a disposable filesystem using system command doubles. It compares the existing configuration, state and launchers after the second bootstrap, checks isolated enrollment and bridge configuration, and checks that systemd only receives a reload. This does not qualify real system users, ACLs or SSH service configuration.

The issue-to-review test uses actual SQLite, helper-created Git checkouts, Git bundles and pushes to a disposable local Git remote. Controlled GitHub and Codex peers first pass CI on one commit, then keep returning its successful workflow receipt while a newer commit is published. The coordinator is closed and reopened. It retains the same run, checkout, session and PR, and returns issue progress to review only when the test peer supplies CI evidence for the newer commit. A live private source App, the shared production Codex App Server and installed service recovery require their own operator evidence. W04/W06 and the integrated acceptance statuses remain unchanged.
