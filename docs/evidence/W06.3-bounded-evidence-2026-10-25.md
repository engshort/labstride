## Implementation

- Versioned operational events accept fixed reason codes, correlation IDs and timestamps. Metrics contain numeric aggregates without task/session labels. Arbitrary strings that happen to resemble codes map to a safe fallback. CLI/bridge/summary views omit untrusted error messages.
- New action error receipts retain validated codes and retry classifications while omitting raw messages and unverified diagnostic evidence IDs. Observation logs omit arbitrary resources/outputs. Session intent logs retain identity/digest metadata rather than prompt text. Independently bound handles, outcomes, resource inventory, evidence references and private operational descriptors survive.
- Workflow receipt storage retains the original payload digest for exact duplicate/conflict detection alongside safe error diagnostics. No signed artifact is rewritten. Existing historical records and backups are not retroactively scrubbed.
- Zero configured repairs prevents a repair request and persists its reason while allowing initial non-repair work. Scheduling and effect gates retain the configured repair/time limits. Restart and ordinary resume do not reset them. Exhaustion does not stop original-result reconciliation or fabricate cancellation.
- Public Project and native-field profiles publish one bounded managed summary with the configured repository credential. Summaries explain holds and budget usage without granting action/field effects. Emergency policy pause, restore fences, manual edits and unknown mutation results remain protected.
- Migration 21 adds a narrow SQL deletion guard, an indexed diagnostic eligibility view and immutable retention batch records. Explicit CLI preview/apply requires the service lock, an existing compatible database and no restore fence. Apply removes at most 500 expired redundant diagnostics in one transaction, preserving original handles and immutable recovery/audit/resource evidence.

The normative behavior, metric definitions, eligibility exclusions and rollback limits are documented in [operations](../16-operations-and-cli.md). The operational database remains private: persisted descriptors and action-specific outputs needed for recovery are not a public logging API. Retention compacts diagnostics, not the entire durable database; managed sessions and uncorrelated records are conservatively retained.
